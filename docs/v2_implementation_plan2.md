# LearningPath AI — Revised V2 Implementation Plan

Oct 13, 2026 · revised for Qdrant and the transcript review

V2 adds saved learning paths and curriculum-scoped transcript Q&A in checkpoints 7–14, estimated at 17–24 hours across three focused days. This replaces the V2 section of `implementation_plan.md`; V1 checkpoints 1–6 stay as they are.

## Scope decisions and flagged adjustments

**1. The demo curriculum will not match the library on its own.** V1 searches all of YouTube, so a freshly generated Python curriculum will rarely recommend any of the 28 library videos. Without a fix, requirement 7.5 (several indexed videos in the saved curriculum) cannot be met. Smallest adjustment: a small curation helper that attaches chosen library videos to a saved curriculum's modules by video ID, taking title and URL from the transcript manifest, so every record is genuine. Saved videos get a `source` field (`youtube_search` or `library`) so the demo is honest about which is which. Automatic matching of modules to library videos is deliberately excluded; it borders on curriculum rewriting, which section 6 rules out.

**2. Transcripts: reviewed, 28 usable.** Every file has the video title on line 1 and its YouTube URL within the first 4 lines, so the manifest is generated by code, not by hand. Two timestamp styles exist, and both can be parsed:

- **Standard (24 files):** a time such as `4:11` alone on a line, followed by a line of text.
- **Merged (4 files):** time, spoken duration and text run together, for example `0:077 secondsWelcome to...` or `1:00:031 hour, 3 seconds...`.

Chapter headings (such as `Static methods`) appear as text lines without a time. One file, `First LIVE Agent Build - Fullstack RAG Agent for YouTube Content.txt`, contains the transcript of the "50 Advanced Python Concepts" video under the wrong title and URL; it is removed from the library. Timestamps are never reconstructed: a chunk whose start time cannot be read stores `None` and links to the video without `&t=`.

**3. Checkpoint 6 is still open.** `README.md` is empty on `main`, and `uv run youtube-university` points to the placeholder in `__init__.py`. Both are V1 fixes, made on `main` and merged into `v2-rag`.

**4. Stack choices.**

- Persistence: one JSON file per learning path in `data/curricula/`, written and read through Pydantic.
- Embeddings: `nomic-embed-text` through the Ollama you already run; no PyTorch install.
- Vector store: Qdrant local mode, `QdrantClient(path="data/qdrant")` (Git-ignored), cosine distance, payload filter for curriculum scoping. ChromaDB 1.5.9 crashed natively on insert (Windows access violation) and was dropped.
- Generation: `llama3.2:3b`, as in V1. No LangChain; the direct calls are a few lines each.

**Answered questions**

- Transcript format: see scope decision 2.
- V1 stores videos as plain dicts (`video_id`, `title`, `channel`, `url`), built in `youtube.find_videos`; checkpoint 8 adds a `Video` model with those fields plus `source`.
- `main()` already holds everything a saved path needs: the `profile` dict, the `Curriculum`, and `results`, a list of `(module, videos)` pairs.

## Day 1: checkpoints 7–9

### Checkpoint 7 — Transcript headers and manifest

- **Purpose:** give every transcript a genuine video ID and title, generated from the files themselves.
- **Build:** `read_header(path)` reads the title, video ID and timestamp style of one file; `build_manifest()` writes all of them to `data/transcript_manifest.csv`. Remove the mismatched file first.
- **Files:** new `src/youtube_university/transcripts.py`, `data/transcript_manifest.csv`, `docs/dev_log.md`.
- **Concepts:** `pathlib.Path` and `glob`, `encoding="utf-8-sig"`, compiled `re` patterns, `@dataclass`, Python's `for ... else`, `csv.writer` with `newline=""` on Windows.
- **Done when:** `uv run python -m youtube_university.transcripts` reports 28 transcripts (24 standard, 4 merged), every video ID is 11 characters, and the manifest is committed.
- **Time:** 45 min–1 h.

### Checkpoint 8 — Save, list and load learning paths

- **Purpose:** a generated curriculum survives a restart without calling Ollama or YouTube again.
- **Build:** a `SavedLearningPath` model (id, created time, profile, curriculum, videos per module, each video with `source`), plus `save_path`, `list_paths` and `load_path`. One JSON file per path, named by its id.
- **Files:** new `storage.py` (models plus save/list/load; imports `Curriculum` from `llm.py`, so no V1 code moves), `main.py`, `tests/test_storage.py`.
- **Concepts:** Pydantic `model_dump_json()` and `model_validate_json()` (comparable to `System.Text.Json` with validation built in), `uuid4().hex` ids, timezone-aware `datetime.now(timezone.utc)`, pytest's `tmp_path` fixture for writing to a throwaway folder.
- **Done when:** a round-trip test saves and reloads a path and the two models compare equal; listing returns paths newest first; loading a missing or corrupted file raises a clear error naming the file.
- **Time:** 2.5–3.5 h.

### Checkpoint 9 — Terminal menu for new and saved paths

- **Purpose:** wire Options A and B into the existing terminal app.
- **Build:** a main menu (new path, open saved path, quit); after generating, a save prompt; after opening, a review screen with an "ask a question" option stubbed for now.
- **Files:** `src/youtube_university/main.py`.
- **Concepts:** keeping input loops separate from logic so the logic stays testable; `match` statements (Python 3.10+, similar to a C# `switch` expression).
- **Done when:** generate → save → quit → restart → open shows the same curriculum and videos, with Ollama stopped during the reopen to prove nothing is regenerated; invalid menu input re-prompts instead of crashing.
- **Time:** 1–1.5 h (merge into checkpoint 8 if it runs short).

## Day 2: checkpoints 10–12

### Checkpoint 10 — Parse and chunk transcripts with timestamps

- **Purpose:** turn each file into chunks that carry their video ID, title and start time from the moment they are created.
- **Build:** a parser that yields `(start_seconds, text)` segments for both timestamp styles (standard and merged), skipping chapter headings, and a chunker that groups consecutive segments into roughly 150–250 words with one segment of overlap. Each chunk keeps the start time of its first segment and a stable id such as `<video_id>_0007`.
- **Files:** `transcripts.py`, `tests/test_transcripts.py` with a small sample transcript under `tests/fixtures/`.
- **Concepts:** generator functions with `yield` (the same idea as C# `yield return`), `re` named groups, `@dataclass` for a lightweight chunk record (similar to a C# record), converting `h:mm:ss` to seconds.
- **Done when:** tests pass for both timestamp styles (including hours and a line without a time), chunk overlap and stable ids; all 28 files parse with zero empty chunks; the total chunk count is logged.
- **Time:** 2.5–3.5 h.

### Checkpoint 11 — Embedding index in Qdrant

- **Purpose:** index once, reuse on every run.
- **Build:** a `build_index` command that embeds chunks in batches with `nomic-embed-text` (prefix `"search_document: "`) and upserts them into a Qdrant collection in `data/qdrant/`. The collection is created only if `collection_exists` is false, with cosine distance and the vector size taken from the first embedding. Point IDs are `uuid5` values built from `<video_id>_<chunk_index>`. Payload per chunk: `video_id`, `title`, `start_seconds` (or `None`), `chunk_index`, `text`. Run it on 3 transcripts first, time it, then run the rest.
- **Files:** new `index.py`, a small script or menu option to build the index.
- **Concepts:** what an embedding is and why queries and documents must use the same model; batching; `upsert` with stable IDs (re-running replaces rather than duplicates); Qdrant point IDs must be integers or UUIDs; local mode locks its folder, so one `QdrantClient` per run, passed to the functions that need it.
- **Done when:** the point count equals the chunk count; running the build a second time leaves the count unchanged; per-chunk embedding time is recorded in the dev log.
- **Time:** 2–3 h.

### Checkpoint 12 — Curriculum-scoped retrieval and the demo curriculum

- **Purpose:** search only the videos that belong to the open learning path.
- **Build:** `indexed_video_ids(path)` returns the curriculum's video IDs that exist in the index; `search(question, video_ids, k=4)` embeds the question (prefix `"search_query: "`) and calls `client.query_points` with a `FieldCondition(key="video_id", match=MatchAny(any=video_ids))` filter. Then the curation helper from scope decision 1 attaches several library videos to a saved "Python for AI development" curriculum generated by V1.
- **Files:** `index.py` (or a new `retrieval.py`), `storage.py` (curation helper), `tests/test_retrieval.py`.
- **Concepts:** vector search and cosine similarity (Qdrant scores: higher is closer); payload filtering; reading scores to calibrate what a weak match looks like.
- **Done when:** a test asserts that every returned chunk's video ID is in the curriculum; a curriculum with no indexed videos returns a clear message without querying Qdrant (never send an empty `MatchAny` list); the saved demo curriculum shows at least four indexed videos; scores for three on-topic and two off-topic questions are logged.
- **Time:** 2–2.5 h.

## Day 3: checkpoints 13–14

### Checkpoint 13 — Grounded answers with timestamped links

- **Purpose:** answer only from retrieved passages and show exactly where each claim came from.
- **Build:** a prompt that numbers the retrieved passages `[1]`–`[4]` with their video titles, tells the model to answer only from them, cite with `[n]`, never invent code that is not in the text, and reply with a fixed "could not establish this from the indexed videos" sentence when the passages do not cover the question. After generation, parse the `[n]` citations and show only the sources actually cited, each with `https://www.youtube.com/watch?v=VIDEO_ID&t=251s` (or no `&t=` when the start time is `None`). If the best score is below the threshold from checkpoint 12, skip the LLM call and return the refusal directly.
- **Files:** new `qa.py`, `llm.py` (reuse the existing Ollama call), `tests/test_qa.py`.
- **Concepts:** context injection; grounding and refusal; why citations are validated in code rather than trusted; a low temperature for factual answers; Ollama's context length limit (keep 4 chunks of about 200 words).
- **Done when:** with Ollama mocked, tests confirm that citations map to the right titles and links, an uncited or out-of-range `[n]` is dropped, and a weak retrieval skips the LLM; live, three supported questions cite the correct videos and their links open within about 30 seconds of the relevant passage.
- **Time:** 3–4.5 h.

### Checkpoint 14 — Q&A in the menu, evaluation and demo

- **Purpose:** close the vertical slice and prove it holds up.
- **Build:** connect the "ask a question" option from checkpoint 9 to `qa.py`; show which videos in the path are indexed before the first question. Write six evaluation questions: three the transcripts answer, two they do not (including one about on-screen code), and one asked on a curriculum with no indexed videos. Update the README, dev log and V2 checklist; tag `v2.0-rag`.
- **Files:** entry point, `docs/eval_questions.md`, `README.md`, `docs/dev_log.md`.
- **Concepts:** end-to-end manual testing against acceptance criteria; recording known limitations honestly.
- **Done when:** the seven-step demo in requirements section 7 runs start to finish after a restart, and all six evaluation questions behave as expected (answer with sources, or a clear refusal).
- **Time:** 2.5–3.5 h.

## Technical risks

The transcript format is now settled; the demo-curriculum gap is settled in checkpoint 12.

| Risk | What can go wrong | Mitigation | Settled in |
| --- | --- | --- | --- |
| Transcript parsing | Two timestamp styles; chapter headings mixed into the text; byte-order marks; a file whose content does not match its title | Manifest generated by code; one parser per style, both tested; mismatched file removed; check new files against their titles | CP7, CP10 |
| Timestamp accuracy | Caption times drift; a link points to the chunk start, not the exact sentence | Keep each chunk's first-segment time; chunks of 150–250 words keep the jump within about a minute; no `&t=` when unknown | CP10, CP13 |
| Video-ID matching | IDs are case-sensitive 11-character strings; V1 search almost never returns library videos | Extract IDs with one tested pattern; compare exact strings; curation helper for the demo curriculum | CP7, CP12 |
| Embedding performance | Embedding the full library on CPU takes minutes; three transcripts are 400–750 KB each; Ollama may swap between the embedding model and `llama3.2:3b` | Batch requests; time 3 transcripts first; index once with upsert; demo can run on the demo curriculum's subset | CP11 |
| Curriculum-scoped search | Search leaks into unrelated transcripts; empty filter list; fewer matching chunks than `k` | `MatchAny` filter on `video_id` with a test asserting scope; check for zero indexed videos before querying | CP11, CP12 |
| Qdrant local mode | A second client on the same folder fails; non-UUID point IDs are rejected | One client per run; `uuid5` point IDs | CP11 |
| Small-model compliance | `llama3.2:3b` may skip citations, cite passages that were not given, or invent code | Numbered passages, strict instructions, low temperature; citations validated in code; refusal path that skips the LLM on weak retrieval | CP13 |
| Library versions | `qdrant-client` has deprecated older calls such as `search` | Use `query_points`; the exact version is pinned in `uv.lock` | CP11 |
